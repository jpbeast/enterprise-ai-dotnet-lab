# Project Context

## Identity
**Modern Enterprise .NET + AI — building AI-enabled systems without abandoning good engineering.**

This is an independent eight-week GitHub learning and LinkedIn series. The primary professional positioning is Senior .NET Engineer / Technical Lead expanding into practical AI-enabled application development, not a pure AI Engineer.

## Objectives
- Learn modern .NET and practical AI integration by implementing working code.
- Evolve one public GitHub portfolio repository rather than many disconnected demos.
- Emphasize enterprise architecture, maintainability, security, observability, testing, performance, cost and trade-offs.
- Build practical foundations for future AI-901 study.
- Publish LinkedIn content only from completed, verified hands-on work.

## Workflow
Learn → Setup → Build → Test → Debug → Measure → Document → Commit → Publish → Create LinkedIn Content.

## Delivery principles
- Begin with the minimum architecture needed and add components when justified.
- Default to free/local tools where practical.
- Explain billing requirements, charge triggers, cost controls and cleanup before using paid/cloud resources.
- Never treat proposals, suggestions or unverified reports as completed implementations.
- Keep secrets, credentials and client-owned code or data out of this public repository.
- Record actual tests, evidence, limitations and decisions before publishing claims.

## Eight-week outline
1. Microsoft.Extensions.AI and IChatClient — provider-independent AI integration.
2. MCP Server in C# — tools/resources, authorization and audits.
3. RAG in .NET — ingestion, chunking, embeddings, vector search, retrieval evaluation.
4. Agentic Workflows — agent execution vs deterministic workflows.
5. .NET Aspire — local orchestration of application services.
6. AI Observability — OpenTelemetry across API, model, tools and data.
7. Model Routing & Failover — reliability, latency and cost comparison.
8. Production Hardening — evaluation, tests, security, resilience and final assessment.

## LinkedIn
Monday: implementation, design choices and repository milestone after verified work.
Friday: evidence-based demo, experiment, trade-off, failure analysis, benchmark or technical lesson.

GitHub implementation → LinkedIn technical insight → community feedback → next GitHub experiment.
